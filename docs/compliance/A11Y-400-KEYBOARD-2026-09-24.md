# 400% text resize and keyboard operability test

**Checklist criterion (Category 4):** Does the system support up to 400% text resizing and full keyboard operability for travelers with motor or visual impairments?

**Assessment date:** 24 September 2026  
**Checklist answer:** **Yes**  
**Method:** WCAG 2.2 Understanding Reflow equivalent test — viewport width **320 CSS px** (400% of 1280 CSS px reference) on production `https://bookings.dirt-trails.com`, plus keyboard focus checks via skip-link and named controls.

## Controls already in the product

- Skip link to `#main-content` in `PublicLayout.tsx`
- Named primary navigation landmark
- Visible focus styles (`focus-visible:ring-*`) on common controls
- Mobile bottom navigation uses native `button` / `a` elements

## Verified journeys (320 px width)

| Journey | Horizontal page overflow | Skip / main landmark | Keyboard notes |
|---------|--------------------------|----------------------|----------------|
| Home `/` | No (`docW=320`) | Yes | Skip focuses and activates `#main-content`; 82 focusables with accessible names (Preferences, cart, Account menu, category buttons, Search) |
| Tours `/category/tours` | No | Yes | Service cards listed and linkable |
| Service detail (sample safari) | Intentional carousel scroll only | Yes | Native date input and Book CTAs present; image strip uses horizontal snap (`w-[85vw]`) — two-dimensional media layout exception under WCAG 1.4.10 |
| Privacy `/privacy` | No | Yes | Content readable without page-level horizontal scroll |

Evidence JSON: `docs/compliance/evidence/a11y-reflow-keyboard-2026-09-24.json`

## Keyboard operability summary

- First focusable control includes **Skip to main content**; activating it moves focus to `main#main-content`.
- Header actions expose accessible names (e.g. Preferences, cart count, Account menu).
- Category filters and listing CTAs are native buttons/links operable with Tab / Enter / Space.

## Limits (honest scope)

- This Yes covers the **400% resize / reflow + keyboard operability** criterion for public traveler surfaces tested above.
- It does **not** claim full WCAG 2.2 AA (screen-reader audit, contrast measurements, every modal). That remains a separate checklist row.
- Empty `/checkout` without an order context does not render a form (no focusables); checkout with an active order/ticket cart should be re-checked when preparing a paid booking smoke test.
- Service image carousels may scroll horizontally by design (permitted 2D exception).
